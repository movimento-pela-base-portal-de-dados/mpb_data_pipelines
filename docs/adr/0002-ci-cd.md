# ADR 0002: CI/CD do orquestrador Prefect

- Status: aceita
- Data: 2026-10-19

## Contexto

O deploy no orquestrador (ADR 0001) era manual e não tinha verificações após o
deploy. O time quer três etapas: testes no PR, deploy no merge com a imagem
gerada no PR e verificações depois do deploy.

## Decisão

- **Tag por árvore git.** A imagem dos flows recebe a tag `tree-<git rev-parse HEAD^{tree}>`.
  O PR testa `refs/pull/N/merge`, cuja árvore é a que a `main` recebe no merge.
  Como a `main` exige branch atualizada (`strict status checks`), squash, merge
  commit e rebase geram a mesma árvore. O CD encontra a imagem do PR sem rebuild.
- **PR.** `lint` e `tests`, depois o job `Image`: build, teste de integração com
  a stack Compose e o flow `healthcheck`, e push ao ECR. Só PRs do próprio
  repositório fazem push, por OIDC, sem credenciais estáticas.
- **Fallback.** PRs de forks e do Dependabot não recebem token OIDC. Quando a
  tag não está no ECR, o CD gera, testa e envia a imagem.
- **Deploy.** O CD assume uma role por OIDC (environment `production`) e envia
  comandos à EC2 por SSM Run Command. Nenhuma porta é aberta.
- **Pós-deploy.** `orchestrator/bin/check.sh` verifica a API, o work pool, a
  imagem de cada deployment e executa o flow `healthcheck`.
- **Rollback.** Se o deploy ou as verificações falham, o CD volta para a última
  versão aprovada (`/var/lib/mpb-prefect/last-good`). O workflow continua com falha.
- O deploy é automático no merge. A revisão do PR é a aprovação.

## Alternativas consideradas

- Runner self-hosted na EC2: risco de segurança em repositório público.
- API Prefect exposta por load balancer: exige TLS e endpoint público.
- Push para o GHCR e cópia para o ECR no merge: evita AWS no PR, mas publica a imagem.
- Rebuild no merge: a imagem implantada não seria a imagem testada.

## Consequências

- O CI de PR usa AWS por OIDC. A regra do `CONTRIBUTING.md` foi ajustada.
- O check obrigatório `Image / Image build and integration` entra na ruleset da `main`.
- Imagens de PRs não aprovados ficam no ECR até a lifecycle policy expirá-las.
- Os workflows ficam inativos até o mpb-infra entregar as roles e as variáveis.
- Mudanças em `orchestrator/` reiniciam os serviços durante o deploy.
